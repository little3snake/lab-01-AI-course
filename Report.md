## Part 2

Исходный `part2_measure.py` для Claude сохранён и создан отдельный **`part2_measure_gemini.py`**:

- `genai.Client()` и `client.models.count_tokens()` используются для подсчёта всех элементов `CORPUS`.
- `client.models.generate_content()` отправляет `complaint` как пользовательский текст, а `system_prompt` — через `system_instruction`.
- Параметры: `temperature=0.2`, `max_output_tokens=2048`, выбор модели через `--model`, генерация только с `--call`.
- Из `usage_metadata` читаются `prompt_token_count`, `candidates_token_count`, `thoughts_token_count`; в `output_tokens` сохраняется сумма видимого ответа и thinking.
- `request_tokens` берётся из usage реального запроса, а не из суммы отдельных измерений текстов. Без `--call` в этой адаптации `request_tokens` не заполняется.
- JSON содержит провайдера, модель, `token_counts`, `request_tokens`, `one_request_billed`.

### Расчёта на Gemini

Созданы:

- **`prices_gemini.py`** — `ModelPrice`, таблица `MODELS`, источник и дата цен, функция `cost_usd`. Сейчас в `MODELS` только `gemini-3.6-flash`.
- **`part3_cost_gemini.py`** — чтение `measurements_gemini.json`, расчёт стоимости запроса и года, отношений input и bill, параметров `--measurements`, `--model`, `--requests-per-day`, `--output-tokens`.

В расчёте использованы Standard цены за 1 млн токенов (на момент 17.09.26):

| Модель | Input, USD | Output с thinking, USD |
|---|---:|---:|
| Gemini 3.6 Flash | 0.75 | 3.75 |
| Gemini 3.5 Flash-Lite | 0.30 | 2.50 |

Источник: [официальная таблица Google](https://ai.google.dev/gemini-api/docs/pricing), проверена 17.09.2026. Для Flash тариф 0.75/3.75 указан до 31.12.2026; с 01.01.2027 страница указывает 1.50/7.50.

```text
Стоимость запроса, USD = (input × цена_input + output × цена_output) / 1 000 000
Стоимость года, USD = стоимость запроса × запросов_в_день × 365
output = видимый ответ + thinking
```

Выполнено также на 5000 запросов в день:

```powershell
python part3_cost_gemini.py
python part3_cost_gemini.py --requests-per-day 5000
```

В рассчет идет только SYSTEM_PROMPT + COMPLAINT из текстов

```text
                              EN          RU          KK
input tokens                 101         131         237
output tokens                423         755        1038
cost, US cents            0.1662      0.2929      0.4070

AT 2,000 REQUESTS/DAY -- US dollars per year
gemini-3.6-flash           1,213       2,139       2,971

AT 5,000 REQUESTS/DAY -- US dollars per year
gemini-3.6-flash           3,033       5,346       7,428

input only                 1.00x       1.30x       2.35x
total bill                 1.00x       1.76x       2.45x
```

При 2 000 запросов в день доплата относительно EN: RU **925 USD/год**, KK **1 758 USD/год**. При 5 000: RU **2 313 USD/год**, KK **4 395 USD/год**.
 Была найдена информация, что в среднем в банки приходит 2к-7к запросов в день, поэтому для второго измерения (5к) была взята цифра из этого диапазона.

**Вывод:** отношение input не равно отношению итоговой стоимости. Для KK они составляют 2.35× и 2.45× соответственно,
потому что оплачивается ещё и разная длина output, включая thinking.

**Задание:** сравнить две казахские фразы близкой длины: только с буквами, общими с русским, и с большим количеством казахских букв; сопоставить bytes/char и токены.

| Казахский текст | Символы | Байты | bytes/char | o200k_base | cl100k_base |

### Core Task 3

**Задание:** заранее предсказать направление изменения, представить жалобу JSON-объектом и измерить абсолютную прибавку токенов в каждом языке.

**Прогноз из блокнота:** JSON потребует больше токенов из-за ключей, кавычек, двоеточий и скобок.

В`texts.py` создан `COMPLAINT_JSON`. Реально использована обёртка `{"complaint":"<исходная жалоба>"}`: текст жалобы не менялся. Это JSON с одним полем, а не разложение фактов по полям `opened`, `rate` и тп.

Команда: `python part0_tokenizers.py`.

| Токенизатор | EN: prose → JSON | RU: prose → JSON | KK: prose → JSON |
|---|---:|---:|---:|
| o200k_base | 59 → 64 (**+5**) | 80 → 85 (**+5**) | 118 → 123 (**+5**) |
| cl100k_base | 59 → 64 (**+5**) | 146 → 151 (**+5**) | 265 → 270 (**+5**) |

**Вывод:** прогноз подтвердился. Просто с оберткой получилось на пять токенов больше во всех языках. Для другого JSON с несколькими полями нужно измерять заново, но пока надбавка идет только за оформление json.
